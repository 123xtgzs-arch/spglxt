# GraalVM 原生发布（与 ysname 相同）

## 最终产物

```
spglxt/              ← 与 ysname 相同
├── spglxt           ← 单个 Linux 原生程序（~90MB），服务器 **不需要 Java**
└── config/          ← 配置（.env、采集 json）
```

对比 TW 视频系统：

```
ysname/
├── ysname           ← GraalVM 原生 ELF
└── config/
```

## 方式一：宝塔服务器上编译（推荐，无需 Docker）

1. 将整个 `java_project` 上传到宝塔，例如 `/www/wwwroot/spglxt-src/`
2. SSH 执行：

```bash
cd /www/wwwroot/spglxt-src
chmod +x deploy/build-native-linux.sh
./deploy/build-native-linux.sh
```

3. 得到 `release/spglxt/spglxt` + `release/spglxt.zip`
4. 将 `release/spglxt/` 移到运行目录 `/www/wwwroot/spglxt/`
5. 宝塔 **Go 项目**：启动文件 `spglxt`，端口 `8080`

```bash
chmod +x /www/wwwroot/spglxt/spglxt
```

脚本会自动下载 GraalVM CE 17 并安装 `native-image`，首次编译约 10–20 分钟，需 4GB+ 内存。

## 方式二：GitHub Actions 编译（Windows/Mac 均可，推荐）

无需本机 Docker、GraalVM，在 GitHub 云端 Linux 环境编译。

1. 将 `java_project` 推送到 GitHub 仓库
2. 打开仓库 → **Actions** → **Build Linux Native**
3. 点击 **Run workflow** 手动触发（或推送代码自动触发）
4. 编译完成后（约 15–30 分钟），在 **Artifacts** 下载 **`spglxt-linux-native`**（即 `spglxt.zip`）
5. 上传宝塔解压，启动文件 `spglxt`

产物与 ysname 相同：**Linux 原生 `spglxt` + `config/`，服务器无需 Java**。

## 方式三：Windows + Docker 编译 Linux 包

安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/) 后：

```bat
build-release.bat
```

选择 **2**，或单独运行 `build-native-docker.bat`。

产物：`release/spglxt/spglxt` + `spglxt.zip`，可直接上传宝塔。

## 方式四：macOS 本地编译

| 目标 | Mac 能否直接做 |
|------|----------------|
| macOS 本机测试 | ✅ `chmod +x deploy/build-native-mac.sh && ./deploy/build-native-mac.sh` |
| Linux 宝塔包 | ❌ GraalVM 不能从 Mac 交叉编译 Linux 原生程序 |

Mac 要打 **Linux 宝塔包**，请用：

- **GitHub Actions**（推荐，见方式二）
- Mac 上装 **Docker**，在项目目录执行与 Windows 相同的 Docker 构建
- 宝塔 SSH 运行 `deploy/build-native-linux.sh`

安装 GraalVM（仅 macOS 本机测试）：

```bash
brew install --cask graalvm-jdk-17
gu install native-image
brew install maven
./deploy/build-native-mac.sh
```

## 方式五：Windows 本地 GraalVM（仅 Windows 测试）

安装 GraalVM JDK 17 + `native-image` + Visual Studio Build Tools，运行：

```bat
build-release.bat
```

选择 **1**，或单独运行 `build-native.bat`。

得到 `release/spglxt/spglxt.exe`（**不能用于 Linux 宝塔**）。

## 宝塔配置

| 项 | 值 |
|----|-----|
| 项目路径 | `/www/wwwroot/spglxt` |
| 启动文件 | `spglxt` |
| 端口 | `8080` |
| 配置 | `config/.env` |

编辑 `config/.env` 中的数据库、Redis、端口后启动。

## 常见错误

| 错误 | 原因 | 处理 |
|------|------|------|
| `cannot execute binary file` | 上传了 `.exe` 或 JAR | 必须用 Linux 版 `spglxt` 原生二进制 |
| `Permission denied` | 未加执行权限 | `chmod +x spglxt` |
| 启动后连不上数据库 | `.env` 未改或 MySQL 未启动 | 检查 `config/.env` 与 MySQL 服务 |

**不要**把 JAR 填成启动文件；**不要**上传 Windows 的 `spglxt.exe` 到 Linux 服务器。
